**口播演讲词**：
> “各位老师、同事大家好，今天汇报我们近期完成的**工程量清单语义标准及智能价格匹配系统（BOQ Intelligence）**的完整工程落地与架构设计。
>
> 我们先看一眼核心目标：造价人员每天面对的最大痛点，不是找不到历史工程文档，而是历史清单命名五花八门、格式极度非标，并且**如果直接用关键词或通用大模型去做纯文本匹配，在工程计价里是会算错真金白银的**。
>
> 【**互动动作 1**：指着屏幕底部默认选中的 **案例 A · 电缆截面 9.0x**】
> 大家看下面这个直接来自我们真实工程数据的例子：左边我们要匹配的目标清单是二级泵站里的 **`ZR-YJV-0.6/1KV-3*150+1*95` 电力电缆**，实际综合单价是 **`1,194.67 元/m`**；而在同一个文件里紧挨着它的另一条是 **`3×25+1×16` 电缆**，单价只有 **`133.15 元/m`**。
> 站在纯文本或纯向量的视角来看，这两条的名字和电压等级几乎一模一样，字面高度重合；但站在工程造价的角度，电缆总截面从 `545 mm²` 降到了 `91 mm²`，价格直接差出 **9.0 倍**！如果系统盲目放行，每一米电缆就会少算一千多块钱。
>
> 【**互动动作 2**：依次点击 **`案例 B · 土石方运距 1.9x`** 和 **`案例 C · 灌木地径 3.3x`**】

>
> 所以我们的系统在设计第一天就立下核心靶心：**不仅要找得像，更要对规格硬约束保持绝对敏感、对单价变更可溯源重算、对高风险错配能主动熔断拦截**。目前系统已经完整接入 **3 个跨越水利生态、土地整治和给排水泵站的真实工程（541 条叶子清单、164 条 L2 工料机单价分析表）**，在 14 条跨省标准验证集上实现了 **100% Top-1/Top-3 命中、0% 硬规格冲突误放行**。”

### Slide 03 · 高内聚低耦合架构与端到端数据流（约 2.5 分钟）

**大屏视觉焦点**：微内核 SVG 全景蓝图（上方 6 大深模块数据流流水线 → 中间 5 个绿色 `Protocol` 端口接缝 → 底部微内核契约与 6 表 SQLite 存储底座）+ 底部 3 卡实时检查器。

**口播演讲词**：
> “接下来汇报系统最核心的工程骨架——为什么我们坚持做**高内聚、低耦合、高可插拔性**的架构。科研和工程最怕的是代码写成一团麻：换个新模型或者多来一种新文件格式，半个项目都要跟着改。
>
> 我们采用了经典的**微内核（Microkernel）+ 六大深模块（Deep Modules）+ 五大端口接缝（Protocol Seams）**架构，大家看到的这张交互图就是整个数据流：
>
> 【**互动动作**：按从左到右依次点击 **`MODULE 01`** → **`MODULE 03`** → **`SEAM 04`** → **`MICROKERNEL CORE`**，展示下方 3 张卡片动态切换】
> 从左往右一条主数据流清晰串联全过程：
> 1. **`01 异构接入模块`（`IngestionModule`）** 通过 **`DocumentParserPort`** 屏蔽 `.xls`、`.xlsx`、`.docx`、`.pdf` 的全部解析脏活，向上游只吐出标准的 `RawBoqItem`。将来哪怕要接入广联达 XML，只需新增一个实现类并用 `@PluginRegistry.register("parsers")` 注册 1 行代码。
> 2. **`02 语义标准化模块`（`SemanticStandardizerModule`）** 由 **`01~07` 七份领域 YAML 本体词典**驱动，通过 **`FeatureExtractorPort`** 执行“正则优先（p=10）+ LLM 兜底（p=90）”混合抽取，再做单位制统一，输出带硬规格槽位的 `StandardizedBoqItem`。
> 3. **`03 智能混合检索与重排模块`（`PriceMatchingModule`）** 把召回与重排彻底解耦为 **`RetrieverPort`** 与 **`RerankerPort`**。我们在 `configs/pipelines.yaml` 里直接注册了 4 套管线（生产默认、LSTM 基线、R-GCN 图模型、无衰减消融版），做对比实验或切换模型改 1 行配置即可，主代码一行不改。
> 4. **`04 动态调价模块`（`PriceAdjustmentModule`）**、**`05 合规审计护栏`（`AuditLinterModule`）** 和 **`06 原生公式导出与反馈闭环`（`ExporterModule`）** 也全部只通过微内核定义好的强类型 Pydantic 契约通信，谁都不越界读取别人的内部细节。最底层通过 6 张 SQLite 核心表实现全生命周期可追溯。”

**大屏视觉焦点**：左侧 HTML5 Canvas 实时指数衰减曲线 + 绿区安全带；右侧 L2 柴油价差动态堆叠条 + 与左侧滑块联动的得分权重实时拆解条。

**口播演讲词**：

>
> 先看左边的 **硬规格指数衰减核 $\Phi_k = \exp(-\alpha \cdot \Delta_{\text{rel}})$**：
> 我们的综合匹配分设计为 **`0.65 × 特征槽位分 + 0.22 × 语义向量分 + 0.13 × 上下文分`**，把最大权重交给工程师真正关心的硬性技术指标。同时系统划定一条 **30% 相对偏离安全区**（曲线中的绿色阴影带）。
>
> 【**互动动作 1**：把左侧 `候选规格 x_c` 滑块从 `545` 慢慢往左拖到 `450`（还在绿色安全区），再猛地拖到 `91`（掉出安全区）】

> 【**互动动作 2**：点击右侧的 **`佛山 7.00 元/kg`** 切换到 **`鄂尔多斯 7.40 元/kg`**，或者手动拖动柴油单价滑块】
> 再看右边的 **L2 要素动态组价沙盒**：匹配到历史条目只是第一步，因为广东佛山的柴油 `7.00 元/kg` 不能直接原封不动套给内蒙古鄂尔多斯。系统通过读取 L2 表记录的定额 `10224`（每 `100m³` 消耗柴油 `127.56 kg`，基价 `4.50`），在保留定额直接费 `1539.91` 和间接费利润 `125.51` 不动的基础上，仅实时重算柴油价差与 9% 税金——单价立刻透明、精准地从 **`¥ 21.63 / m³`** 动态更新为 **`¥ 22.19 / m³`**（每方精准上浮 **`+0.556 元`**），每一分钱都给出计算公式。”

## 第二部分：底层机制与设计原理深度参考（应对细节追问随时展开）

### 2.1 端到端全链路数据流（从“脏文件”到“合规成果”）

```text
[原始文件包 .xls/.xlsx/.docx/.pdf]
   │
   ▼  Stage 1: IngestionModule (src/modules/ingestion/service.py)
      └─ 接缝 DocumentParserPort → 多适配器指纹路由 (WaterXls / LandMultiSheet / GbPdf / WordContext)
      └─ 清理空占位列、合并跨行截断文本、栈式还原分部层级树、关联 L2 单价分析表
   │  输出契约: RawBoqItem + PartialContext
   ▼  Stage 2: SemanticStandardizerModule (src/modules/standardizer/service.py)
      └─ 加载 01~07 领域 YAML 本体 (configs/domains/*.yaml) + unit_converter.py 量纲统一
      └─ 接缝 FeatureExtractorPort → YamlRegex (priority=10) + LlmSchema (priority=90)
   │  输出契约: StandardizedBoqItem (含结构化 slots: 规格值/物理单位/AHP权重/hard_constraint标志)
   ▼  Stage 3: PriceMatchingModule (src/modules/matching/service.py)
      └─ Phase 1 知识与单位族过滤 → 同类工程域筛选 + 计量单位量纲同族放行
      └─ Phase 2 多路并行召回 (BM25 + Dense SVD 128维 + Slot精确匹配) → RRF (k=60) 聚合 Top-50
      └─ Phase 3 接缝 RerankerPort (默认 HybridHardSpecKernelReranker) → 指数衰减重排 + SHAP 归因
   │  输出契约: MatchResult (含 Top-K 候选、confidence 绿/黄/红灯、slot_comparisons)
   ▼  Stage 4: PriceAdjustmentModule (src/modules/pricing/service.py)
      └─ 接缝 PriceAdjusterPort 按优先级路由：
         1) 有 L2 构成且命中材料市场价差 → QuotaMaterialDiffAdjuster（逐项重算材差与9%税金）
         2) 同省同周期且无显著变动 → DirectReuseAdjuster
         3) 跨省/跨期但缺 L2 明细 → RegionalTimeIndexAdjuster（区域系数×时间指数折算）
   │  输出契约: AdjustedPriceBreakdown (新综合单价 + 调价公式明细)
   ▼  Stage 5: AuditLinterModule (src/modules/auditing/service.py)
      └─ 接缝 AuditRulePort → 并发执行 BQ001–BQ012 独立检查规则 (bq_rules.py)
   │  输出契约: list[AuditFinding] (如 BQ004 缺失硬槽位、BQ009 离群价、BQ010 低置信阻断)
   ▼  Stage 6: ExporterModule (src/modules/exporter/service.py)
      └─ 写入带原生 Excel 公式 (=ROUND(F*G,2), =SUM(...)) 工作簿 + 审计依据附表 + 反馈闭环入库
```

**数据库 6 张核心溯源表（`src/infrastructure/repositories/sqlite_repo.py`）**：
1. `projects`（L0 层）：省市区、编制阶段、价格基准月、计价依据标准、总造价；
2. `boq_items`（L1 层）：清单编码、分部路径、`standard_name`、`standard_unit`、结构化特征槽位 JSON、综合单价及来源行号；
3. `l2_breakdowns`（L2 层）：定额编号、定额单位、基期直接费/人工费/材料费/机械费/间接费/利润/税费及主材耗量 JSON；
4. `material_prices`：各省各期主要材料（柴油、电缆主材、苗木等）基准单价与信息价；
5. `kg_triples`：工程语义同义词、定额路由与物理量纲换算知识图谱三元组；
6. `feedback_logs`：造价人员人工审核采信/修正日志，用于持续沉淀反哺匹配阈值与规则词典。

### 2.2 高内聚低耦合、高可插拔设计剖析

1. **为什么把每个模块做成“深模块（Deep Module）”？**
   每个核心业务目录（如 `src/modules/matching/`）内部封装了分词器、BM25、SVD 稠密向量索引、RRF 聚合、核函数重排和解释器等多个复杂子组件，但对外仅仅在 `service.py` 中暴露 1 个极简入口方法（如 `PriceMatchingModule.match()`）。外部调用方和 FastAPI 路由完全不需要知道内部是否经过了几路召回、是否做了回退。
2. **“向内依赖 + 5 接缝反转”是怎么保住低耦合的？**
   所有入参与出参模型均锁定在零第三方算法/数据库依赖的 `src/core/contracts/`（基于 Pydantic 不可变数据结构）；5 个核心变化点被抽象为 Python `Protocol`（`src/core/ports/`）。因此，哪怕我们未来把 SQLite 换成企业级 PostgreSQL + `pgvector`，或者把字符级 TF-IDF+SVD 替换成 GPU 部署的 `BGE-M3` 向量模型，上层核心业务流水线和下游审计/导出代码**一行都不需要改**。
3. **热插拔扩展示例（新增 1 种能力只需 1 个文件）**：
   * **扩专业域**（例如新增“海洋生态修复”细节规则或“海工防腐工程”）：直接在 `configs/domains/` 下新增一份 YAML 本体声明同义词和槽位正则即可，零 Python 代码改动；
   * **扩匹配算法**（例如引入大语言模型 Reranker）：实现 `RerankerPort` 接口类并加上 `@PluginRegistry.register("rerankers")`，随后在 `configs/pipelines.yaml` 里把测试管线的 `reranker` 字段改名即可开启无缝 A/B 评测。

### 2.3 智能价格匹配算法数学设计细节

`HybridHardSpecKernelReranker`（`src/modules/matching/rerankers/hybrid_kernel_reranker.py`）对多路 RRF（`k=60`）产生的 Top-50 候选逐一计算综合评分：

$$S_{\text{total}}(q, c) = 0.65 \cdot S_{\text{feat}}(q, c) + 0.22 \cdot S_{\text{sem}}(q, c) + 0.13 \cdot S_{\text{ctx}}(q, c)$$

其中三个分量各自承担不可替代的职责：
1. **特征结构核 $S_{\text{feat}}$（占 65% 主导权）**：
   $$S_{\text{feat}} = 0.80 \cdot \frac{\sum_k w_k^{\text{eff}} \cdot \Phi_k(x_q, x_c)}{\sum_k w_k^{\text{eff}}} + 0.20 \cdot S_{\text{name}}$$
   * 对标有 `hard_constraint = True` 的数值槽位（截面、运距、地径、管径等），采用 **硬规格指数衰减核**：
     $$\Phi_k(x_q, x_c) = \exp\left(-\alpha \cdot \frac{|x_q - x_c|}{\max(|x_q|, |x_c|, 10^{-6})}\right), \quad \alpha = 4.5$$
   * **防误匹配安全闸（硬约束惩罚）**：一旦检测到任一硬规格相对偏差 `rel_diff > 0.30` 或计量单位物理量纲不兼容（如把 `套` 匹配给 `m`），立即标记 `has_hard_spec_conflict = True`，触发复合压制与硬封顶：
     $$S_{\text{total}} \leftarrow \min\left(S_{\text{total}} \cdot (0.45 + 0.55 \cdot p),\ 0.58\right)$$
     保证任何严重违背规格或量纲的候选绝对无法进入黄灯/绿灯区，强行归入 `ConfidenceLevel.LOW` 并被 `BQ010LowConfidenceBlockRule` 拦截。
2. **多模态语义核 $S_{\text{sem}}$（占 22% 权重）**：
   综合稠密向量相似度（字符 `char_wb` 2–4 gram TF-IDF 经 128 维 `TruncatedSVD` L2 归一化内积，无需 GPU 也能捕获子串形态变化）、精确型号 `BM25` 归一分以及槽位/词面重叠度：`0.55 * dense + 0.30 * bm25 + 0.15 * max(slot, jaccard)`。
3. **宏观工程上下文亲和分 $S_{\text{ctx}}$（占 13% 权重）**：
   优先同省份（+0.50）、同编制阶段（+0.25）以及价格基准年更接近的工程（$\exp(-0.15 \cdot |y_q - y_c|)$ 贡献 0.25）。

## 第三部分：组会现场高频 QA 与应答预案

**Q1：既然现在 DeepSeek / GPT 大模型这么强，为什么不直接把清单提示词丢给大模型出报价，而要搞这么多模块和内核数学公式？**
> **回答要点**：两点硬伤。第一是**幻觉与数学不可控**：工程造价要求极高的数字准确性，通用大模型会把“电缆截面 `3*150+1*95`”与“`3×25+1×16`”当成同一种常见电缆胡乱参考报价，而且无法提供确定性的溯源依据。第二是**隐私与成本**：公司历史造价数据和底价涉密，不宜裸奔上传公有云 API；我们这套微内核系统完全支持全离线本地跑通，正则 + SVD + 指数衰减内核毫秒级出结果，大模型仅作为长尾复杂句式抽取（`priority=90`）的可选兜底插件。

**Q2：为什么纯向量检索（哪怕用了 BGE-M3 等顶尖 Embedding）在工程清单上还是容易犯错？**
> **回答要点**：Embedding 模型的训练目标是捕捉“语义主题相关性”而不是“物理数量级比例关系”。在特征向量空间里，“DN200 钢管”和“DN800 钢管”、“运距 0.5km”和“运距 5km”的余弦相似度通常都在 `0.92+`，仅靠向量根本拉不开足够区分度。因此我们必须把特征槽位提出来，给予 **65% 主权重 + 指数衰减核 + 30% 相对偏离直接封顶 `0.58`** 的硬门限机制。

**Q3：以后院里新承接了一个“海上风电海缆敷设”或者“高寒矿区冻土整治”项目，系统怎么扩展？需要重写匹配逻辑吗？**
> **回答要点**：不需要动核心匹配、调价或审计代码。第一步只需在 `configs/domains/` 新增一份该专业的 YAML 领域本体配置，写明核心专业词汇别名、硬规格槽位名（例如水深、抗冻等级）以及对应正则；如果遇到全新的软件导出表格格式，按 `DocumentParserPort` 写 1 个独立解析文件挂载注册即可，底层全部自动复用。

**Q4：历史上很多外省老工程并没有留下详细的 L2 工料机定额构成，只有一条 L1 综合单价，这时候调价怎么办？**
> **回答要点**：`PriceAdjustmentModule` 本身就是多策略分级兜底链：它首先判断命中候选是否拥有 L2 工料机数据，有则运行精度最高的 `QuotaMaterialDiffAdjuster` 逐项重算柴油等主材价差和税费；如果确实缺乏 L2 拆解表且属于跨省/跨年，系统会自动平滑降级至 `RegionalTimeIndexAdjuster`，结合 L0 记录的省份与价格基准月做宏观时间指数与地区系数微调，并在前端明确标记为“指数估算（🟡 黄灯提示复核）”交由造价师把关。

**Q5：为什么前端明明已经有汇总展示，还要在导出模块费力写入原生 Excel 公式？**
> **回答要点**：造价成果交付的最后一公里不是“看网页”，而是进入造价人员的计算底稿并提交审价。静态数字一改数量就会总价对不上，审价单位也不会认。我们通过 `openpyxl` 严格写入 `=ROUND(F*G,2)` 与分部 `=SUM(...)` 原生公式，确保造价员打开导出的表格后直接改几个复核单价或工程量就能自动重算，不改变原有作业惯例。

**Q6：项目已经推到了 GitHub Public 仓库，里面真实的标段文件、金额底价和公司科研申报书不会泄露吧？**
> **回答要点**：绝对安全。我们在 `.gitignore` 中把 `data/` 目录、`*.db`、`*.doc` / `*.docx` / `*.xls` / `*.xlsx` / `*.pdf` 以及公司重点科技项目申报书全部列入了严格忽略清单。公开仓库中运行的是一套脱敏合成演示数据（`_seed_public_demo_projects`），只有您自己本地工作区挂载 `data/` 时，系统启动才会在本地生成私有库用于真实测算，二者完全物理隔离。
