# 0002. 清单语义标准化采用“声明式 YAML 领域特征本体 + 正则优先/LLM 兜底责任链”

工程量清单语义标准化模块（`SemanticStandardizerModule`）在将自然语言项目特征转化为结构化特征槽位（`StandardizedBoqItem`）时，决定采用**声明式 YAML 领域特征本体（`configs/domains/*.yaml`）驱动的“确定性正则解析器优先（Tier-1） → 受控 Schema 大模型抽取兜底（Tier-2）”双层责任链机制**，而非纯大模型抽取或硬编码 Python 解析分支。

水环境综合治理、城乡给排水、水利灌区、煤矿疏干水、土地综合整治、海洋生态修复六大工程领域的分部分类关键词、核心特征槽位定义（实体规格、施工工艺、环境工况）、正则表达式模板、AHP 特征权重以及计量单位换算系数，全部外置保存在 `configs/domains/*.yaml` 中。

## Considered Options

- **方案 A：全量依赖大语言模型（LLM）或序列标注神经网络（BiLSTM-CRF）进行特征抽取**
  - *放弃原因*：真实造价清单中绝大多数核心规格具有高度结构化的工程符号特征（如电缆型号 `ZR-YJV-0.6/1KV-3×150+1×95`、苗木 `地径≥0.3cm`、土方 `运距5km`、混凝土 `C30`）。全量调用 LLM 在批量导入数百上千条清单时耗时过长、算力成本高，且在纯内网离线环境下无法稳定使用。
- **方案 B：在 Python 代码中按工程类型硬编码 `if-else` 正则提取逻辑**
  - *放弃原因*：将工程领域的业务知识写死在代码分支中会导致代码迅速膨胀腐化，技经专家无法直接审阅或调整特征权重，新增工程专业时必须修改核心代码。
- **方案 C：YAML 领域本体配置驱动 + 正则优先 / LLM 强类型兜底责任链（选定方案）**
  - *选定原因*：Tier-1 正则引擎根据 YAML 本体可在毫秒级、零外部依赖下 100% 确定性地抽取出高频标准规格；仅当遇到极其复杂的非标长句且核心槽位未填满时，才按需触发 Tier-2 LLM 抽取器（基于 `Pydantic` 强类型约束输出），兼顾工业级速度、离线可用性与复杂语义泛化能力。

## Consequences

- **新增工程专业零代码改动**：从现有水利、土地整治、安装扩展到煤矿疏干水、海洋生态修复等专业时，技经专家与开发人员只需在 `configs/domains/` 下新增一份 YAML 特征本体配置文件，系统自动加载对应的槽位抽取规则与 AHP 权重。
- **离线确定性保底**：即使在无 GPU、无外网连接的纯内网环境中，系统依然能依靠 Tier-1 领域本体正则引擎与同义词词典完成核心特征拆解与量纲归一化。
