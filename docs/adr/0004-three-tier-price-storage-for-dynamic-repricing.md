# 0004. 价格数据库采用“L0 项目宏观上下文 + L1 清单综合单价 + L2 定额工料机单价分析”三级存储模型

工程价格数据库（`Engineering Price Database`）决定采用**L0（项目宏观上下文与基准信息价）— L1（标准清单与综合单价及人/材/机分项）— L2（定额编号、工料机消耗量与取费计算表）**三级渐进式联动存储模型，而非单一扁平的“清单名称—综合单价”二维表。

脱离了编制地区、价格基准期、造价阶段、计税方式和主要材料基准价的裸单价无法跨项目安全复用。同时，历史造价数据存在显著的颗粒度差异：例如 `data/西柳沟流域生态综合治理工程10.19单行本导表.xls` 仅包含 L1 综合单价（配合 `西柳沟流域生态综合治理工程初步设计概算09.docx` 中的 L0 主材预算价与取费率），而 `data/高明区明城镇全域土地综合整治项目第四批次.xls` 则完整包含 L1 报价表、单价汇总表以及 2564 行 L2 `清单单价分析表4`（含定额编号 `10347+10360`、甲乙类工日、推土机台班消耗量及主次材汇总表）。

## Considered Options

- **方案 A：仅存储扁平的（清单名称、项目特征、单位、综合单价）四元组**
  - *放弃原因*：丢失了省份、年份、定额体系和主材价格基准；当把 2025 年广东佛山的清单单价直接调用到 2026 年陕西西安或内蒙古达拉特旗的新项目时，无法根据两地人工单价和主材（柴油、水泥、砂石、电缆）价差进行科学修正。
- **方案 B：强制要求所有入库项目必须具备完整的定额工料机分解表（L2）才允许入库**
  - *放弃原因*：大量投资估算、初步设计概算单行本或 PDF 报价表（如 `二级泵站电缆综合单价.pdf`、`西柳沟单行本导表.xls`）并不附带逐项定额工料机消耗量明细，强制要求 L2 会导致大量宝贵历史项目无法入库。
- **方案 C：L0 + L1（必选）+ L2（可选增强）三级渐进式联动存储模型（选定方案）**
  - *选定原因*：所有项目入库时均通过“Excel/PDF 计价表 + Word 编制说明”解析构建 L0 项目宏观上下文与 L1 标准清单综合单价；若源数据包含单价分析表，则自动解析挂载 L2 定额工料机消耗量与主材关联。

## Consequences

- **自适应三级调价能力**：系统在为新项目组价时可根据匹配项的数据完整度自动选择最优调价算子：
  1. 若匹配项含 L2 工料机明细且目标项目提供了最新主材信息价，启用**主材价差动态重算算子（`QuotaMaterialDiffAdjuster`）**；
  2. 若匹配项仅含 L0+L1，启用**跨期跨区域指数平滑修正算子（`RegionalTimeIndexAdjuster`）**或**直接复用算子（`DirectReuseAdjuster`）**。
- **多源项目包聚合入库**：文档摄入模块（`IngestionModule`）支持将同一项目的 Word 编制说明与 Excel/PDF 计价表作为统一项目包（`ProjectBundle`）联合解析，将 Word 中的主材基准价和费率自动注入 L0 上下文。
